# 故事扩展方法论（story_expansion_guide.md）

## 用途

阶段 0 的核心方法：把任意厚度的素材（一句话想法 → 完整小说）扩展到"够拍"的完整故事——主题、角色、节拍、节奏全部到位。产物写入 `series.json`（单片项目同样用它，单元数 = 1）。

> 本文件只管**内容侧**（故事该有什么）。视听决策链（情绪/光源/景别/运镜）按 `video_prompt_guide.md` 执行，不在本文件。

## 1. 扩展等级判定

**判据：素材能否回答三问——"主角要什么 / 什么挡着 / 赌注是什么"（不看字数，看事件密度）**

| 等级 | 素材特征 | 三问可答 | 扩展路径 |
|------|---------|---------|---------|
| L0 一句话想法 | 只有角色 + 一个事件（"少年雨夜捡到会倒转的怀表"）| 0/3 | **全扩展**：§2 → §3 → §4 → §6，产出完整 Beat Sheet |
| L1 段落梗概 | 有因果链的 3~5 个事件，角色目标模糊 | 1~2/3 | **中扩展**：§3 补全角色 + §4 定主题 + §6 验证节拍 |
| L2 完整短篇 | 完整事件 + 角色，缺宏观结构（无 A/B、无 set piece）| 3/3 但缺规划 | **结构化**：§5 逐场戏校验 + §6/§7 补装置与曲线 |
| L3 完整小说 | 完整且有体量 | 3/3 且有体量 | **结构化**：压缩 Beat Sheet + scene_distribution（`series_format.md` 原路径）|

> 所有项目（单片/多集/单集）都走此判定，区别只在路径深度；多单元项目另加 0b 分集。

## 2. 高概念门（扩展前必过）

**logline 公式**（沿用 `series_format.md`）：主角 + 主动目标 + 核心障碍 + 赌注。

**三测试，逐条过，不过先改素材**：

| 测试 | 问句 | 不过 → 修法 |
|------|------|-----------|
| 共情入口 | 观众在乎的是什么？必须落在一个**基本驱动**上（守护家人/求存/复仇/被理解/自由…），不是"这个世界设定很酷" | 主角目标不是基本驱动 → 改写目标 |
| 冲突独特性 | "如果 X 会怎样"压力测试：核心冲突只是换皮的既有名作吗？ | 是换皮 → 找区分点（倒置设定 / 新约束 / 类型混搭） |
| 赌注可感知 | 主角失败，失去的东西**具体可见**吗？ | "他只是不开心" → 把赌注落到"谁失去什么" |

**门的输出**：结论写入 `series.json` 的 `gate` 字段（等级 / logline / 三测试结论）；用户确认后才进 §3。
**不过门的处理**：agent 出 **2~3 个修改方案**（按上表"修法"列生成），用户选定或直接改写；3 轮内定不下来 → 项目搁置，不硬扩展。

### 2.5 前提是暴君（Egri，扩展前定死）

- **前提三要素** = 人物特质 + 导致 + 结局（"节俭导致浪费"式，一句话）；好前提是全片最精短的提要，且必须带**作者信念**（"你支持哪一边"）——外来的、你不相信的前提不属于你
- **一部戏只一个前提**：两个前提 = 往两个方向走；副前提可补充，不可并列
- **前提驱使唯一选择**：从前提能唯一推出人物、斗争阶梯与结局（某选择有多个出口 = 前提模糊，重写）
- **改前提 = 项目重启**：前提变更是最高级决策，必须写 `decision_log`（reason = 为什么推翻原前提）

> 前提随 logline 写进 `gate` 字段；剧本文件反向填表（输入方式）时先从中提取前提，缺项标"缺"。

## 3. 角色设计

### 3.1 主角页（每个主要主角一页，7 项）

| 项 | 问句 | 判据 |
|----|------|------|
| Ghost（创伤）| 什么旧伤塑造了 TA 的"错误世界观"？| 必须是角色**从未正视**的事；伤 = 角色相信的那个 lie 的来源 |
| Want（表层欲望）| 角色明面上在追什么？| 一个具体目标，一句话说清 |
| Need（内在需要）| 角色必须变成什么才能真正得到 Want？| **必须与 Want 冲突**（不冲突 = 角色是纸片，故事没有引擎）|
| Flaw（缺陷行为）| 创伤导致哪些具体行为？| ≥2 个可拍的行为（"拒绝求助 / 推开靠近的人"），不是形容词 |
| 弧线类型 | 正向成长 / 平坦 / 负向堕落 | 判据：成长故事 → 正向；主题"坚守"（如硬汉片）→ 平坦；悲剧 → 负向 |
| 高潮道德抉择 | 结局要主角在什么两难里选？| 两个选项都"对"，选一个要付出代价；**不许外部救援代选** |
| 设计原则 | 一句话角色主题 | 如"求助不是软弱而是答案"；与 §4 主题对齐 |

### 3.2 反派页（与主角页同厚度）

- **镜像**：反派对同一道德问题给"错误答案"（主角"求助是答案" → 反派"求助即毁灭"）
- **对手计划**：与主角计划**同量级**，逐回合推进（reveal-react 循环：主角出招 → 反派出招 → 揭示新信息 → 反应）；反派不许当主角赢球的工具人
- 反派同样有 Want/Need；反派倒下的方式必须是其自身世界观导致

### 3.3 功能配角（每人一个 memorable trait：眼罩/口头禅/动作习惯——服务 feature_anchors）

| 位 | 功能 | 数量 |
|----|------|------|
| 导师 | B 故事载体，前期点出主题（Theme Stated）| 1 |
| 盟友 | 助主角执行计划；可设计为"假盟友"（背叛转折点用）| 1~2 |
| 镜子 | 与主角同源创伤走不同路，放大主题 | 0~1 |
| 调剂 | relief valve，从另一个角度展示主题 | 0~1 |

### 3.4 人物网与冲突快检（主角/反派/配角一次过）

- **太阳系配置**：主角 = 太阳，关键配角 = 行星（存在为刻画主角的维），小角色 = 卫星（一个 memorable trait 即可；加了维就必须再出现）
- **维 = 矛盾**：人物深度来自塑造与真相的矛盾（魅力十足的小偷 / 温柔且狠毒）；主角必须维最多
- **塑造 vs 真相**："他是谁"由最大压力下的选择揭示（他选故他在）；内心与外表相同 = 纸片人
- **冲突四型自检**（每条主线场景）：升级型（攻击→反击更强，前提清晰 + 三维人物）/ 静止型（无信念无决定，风趣对话不推进）/ 跳跃型（人物做出不符性格的举动）/ 预兆型（对后续冲突的承诺）；静止 → 查前提与编排，跳跃 → 补过渡（极端情绪之间必须逐级升级，缺过渡 = 戏剧变情节）
- **对手配置四法**：对抗总和 > 主角（各种力量之和，非仅反派）；给对手一把刀（加强对手/削弱主角有利因素）；**不许请"祥云"**（上级一个电话/公文让一切烟消云散 = 戏死）；报应等同罪过（坏人败亡方式有戏剧性）
- **最强对手常是主角自己的错误信念**（§3.1 Ghost）：内在冲突为主时，外在反派只是载体

### 3.5 动机工具箱（按需取用，不套样板）

| 机制 | 可用效果 |
|------|---------|
| 本我/自我/超我 | 本我 = 坏人（包裹在人衣冠里的野兽），自我 = 主角，超我 = 导师/模范；问"这个角色的模范是谁"即找动机 |
| 武器 = 身份象征 | 主角的武器/车/计算机是身份象征——**让它在高潮扮演角色** |
| 防卫机制 | 角色自己不知道、观众看得见：压抑（一触碰就宣泄）、否认（真信 = 悲剧，欺骗 = 坏人）、投射（把未竟梦想投在孩子身上）、错置（在角色间制造推动剧情的裂痕） |
| 压抑越久释放越强 | 反叛必须始于不公正，升级到"不堪忍受的最后一件事" |
| 恋母线两主线 | 每个故事两条主线之一：道德胜利（超我战胜本我）或 赢得所爱（对抗更强的对手） |

## 4. 主题与 A/B 故事

**主题 = 道德论证**，两步写（禁止写成"家庭最重要"这种口号）：

1. 选**价值极性对**：爱/恨、自由/束缚、信任/防备……
2. 写论证："**X 胜过 Y，因为……**"（"因为" = 全片的设计意图；反派的错误答案在对面）

**A/B 故事分工**：
- A 故事 = 外部事件线（Want → 障碍 → 计划）
- B 故事 = 关系/主题线（导师或伙伴），承载 §4 论证
- **Theme Stated**：前期由 B 故事角色一句台词点给主角（"你今年要学的最重要的事是……"）
- **Synthesis（~80%）**：B 故事人物 + 主题洞察 = A 故事的解法，高潮处主角用它破局

**自检**：删掉 B 故事，高潮还成立吗？成立 → B 故事是装饰，重写。

**三条附加**（主题必须过）：
1. **禁止单词主题**：主题必须是**可争辩的对立命题**（"爱就是一切"是口号，"一个好人在行善的追求中能犯多少恶才变成他所对抗的恶"才是命题）；系列项目登记进 `engine_check.theme_proposition`
2. **反讽型**（McKee）：理想主义（上扬）/ 悲观主义（低落）/ 反讽（单一动作同时正负：正面反讽 = 救赎情节，负面反讽 = 惩罚情节）；gate 阶段定型并写入 `gate` 字段，全片基调依此统一
3. **戏核抽验**（陆军）：写出全片的"戏核"（一个动作/道具/境遇/一句话）——**抽掉它戏还在 = 它是枝叶不是根**；戏核必须在 0a-3 前定死

**三条附加**（主题必须过）：
1. **禁止单词主题**：主题必须是**可争辩的对立命题**（"爱就是一切"是口号，"一个好人在行善的追求中能犯多少恶才变成他所对抗的恶"才是命题）；系列项目登记进 `engine_check.theme_proposition`
2. **反讽型**（McKee）：理想主义（上扬）/ 悲观主义（低落）/ 反讽（单一动作同时正负：正面反讽 = 救赎情节，负面反讽 = 惩罚情节）；gate 阶段定型并写入 `gate` 字段，全片基调依此统一
3. **戏核抽验**（陆军）：写出全片的"戏核"（一个动作/道具/境遇/一句话）——**抽掉它戏还在 = 它是枝叶不是根**；戏核必须在 0a-3 前定死

## 5. 场景设计（scenes[] 每场戏两道判据）

剧本层每个场景必须过 **价值翻转测试 + 三问**（结果写入 `script_format.md` scenes[] 的 `value` 字段）。

### 5.1 价值翻转测试（McKee）

- `value` 字段写法：1 个价值词 + 极性，如 `freedom: bound → free`
- 进入场景 = 极性 A，离开 = 极性 B，**B ≠ A**
- 翻转只有两种机制：
  - **行动**：结果与预期产生 gap（"以为能拿到怀表，结果发现它坏了"）
  - **揭示**：新信息推翻既有判断（"老师其实是另一个时间线的他"）
- **不翻转的戏直接删或并入相邻戏**，没有例外；"情绪升级"不算翻转（平静→更平静 = 废戏）
- **L2/L3 素材豁免**（判据优先，§1 原则的例外出口）：素材里不翻转的场**默认并入相邻场**；确需保留必须写**豁免理由**（如"relief valve，§7.1 强度曲线需要低强度戏"），写在场景卡"段落思想"行；无理由保留 = 违规

### 5.2 三问（Mamet，写戏前逐条回答）

| 问题 | 答不出 → |
|------|---------|
| 这场戏里谁要什么（scene goal）| 删这场戏 |
| 得不到会怎样（stakes）| 戏没有赌注 → 改写 |
| 为什么是现在（触发变化）| 戏不是因果必然 → 挪位或合并 |

### 5.3 晚进早出（Late in, early out）

- **进入**：冲突已经发生才进戏（不写"打招呼/寒暄/上车"成独立场景）
- **离开**：翻转完成 + 留下下一场的悬念
- 场景出口只有两个状态：主角**受挫**或**被教育发现另一条路**（两者都把观众推进下一场）

### 5.4 观众信息位置（可选标注，McKee/Oberg）

观众与角色的信息相对位置决定悬念结构，标注在场景卡"价值翻转"行后（可省略）：

| 位置 | 观众 vs 角色 | 效果 |
|------|-------------|------|
| 全知（dramatic irony）| 观众知道角色不知道的 | 命运感、喜剧反差（观众看角色盲目游戏）|
| 受限 | 观众与角色同步不知 | 悬念（suspense）|
| 惊奇（surprise）| 观众已有判断被新信息推翻 | reveal/payoff 落点 |

> 排布规则：全知戏旁白可"抢跑"；受限戏保持同步；惊奇戏把揭示压在 `payoff_registry` 登记的 beat，不许提前泄。

### 5.5 场景选址十选（scenes[] / 场景卡定地点时做）

- 每个场景列 **10 个替代地点**，挑"能扩展情节 + 让角色有事可做"的那个——不直接选"方便"的默认地点
- 静态地点默认红灯：餐馆 / 车 / 电话亭 / 晚餐桌 / 办公室对质 → 必须替代（示例：上司对峙 → 游泳池：上司遵医嘱来回游，警督沿池边喊话，氯水溅上鳄鱼皮鞋）
- 判据：地点本身能否参与冲突（电梯、脚手架、天气 = 能）；纯容器 = 换

### 5.5 场景选址十选（scenes[] / 场景卡定地点时做）

- 每个场景列 **10 个替代地点**，挑"能扩展情节 + 让角色有事可做"的那个——不直接选"方便"的默认地点
- 静态地点默认红灯：餐馆 / 车 / 电话亭 / 晚餐桌 / 办公室对质 → 必须替代（示例：上司对峙 → 游泳池：上司遵医嘱来回游，警督沿池边喊话，氯水溅上鳄鱼皮鞋）
- 判据：地点本身能否参与冲突（电梯、脚手架、天气 = 能）；纯容器 = 换

## 6. 戏剧装置库

### 6.1 Set piece（每幕 1 个招牌场面）

- 判据：**观众能否用一句话复述**（"他骑着机械龙闯进舞会"）
- 节奏位置：集中在 Fun & Games 段（30%~55%），但每幕至少 1 个
- 写入 `acts[].set_piece`；set piece 必须是信息输出 4 类中的 reveal/action 型场景（见 `series_format.md` 场景→镜头拆分依据）

### 6.2 Midpoint：虚假胜利/虚假挫败

- 50% 处主角"看似赢了或输了"，但**一定是假的**（还没学会主题课，赢了也是误打误撞）
- 判据：Midpoint 后对手的计划才真正开始 → 此前的"胜利"是虚假胜利；主角尚未知道失败的真实原因 → 虚假挫败

### 6.3 Twist 三标准（每个反转逐条过，全过才保留）

| 标准 | 检查 |
|------|------|
| 必然性 | 至少 1 个 setup，位置**先于 payoff 所在幕（单元）至少 1 幕**（单片项目即"前 50%"；多单元项目可跨单元，更早 = 更隐蔽），且埋得观众当时没察觉 |
| 意外性 | 观众事先**无法**一句话剧透（能剧透 = 不是 twist） |
| 后果不可逆 | 揭穿后主角的信息/判断/处境根本改变，回不去 |

### 6.4 setup-payoff 管理

- **payoff 是指南针**：先定"高潮要 pay off 什么"（揭示清单），再倒推 setup 埋在哪
- 写入 `payoff_registry[]`：`id` / `payoff`（描述）/ `setup_beats[]`（beat id 列表）/ `act`
- 两条铁律：
  - 高潮的每个揭示必须有 setup（"这从哪来的？"型反转一律重写）
  - 每个 setup 必须有 payoff（不回收的铺垫 = 烂尾）

## 7. 宏观节奏曲线

### 7.1 百分比曲线（单片/单集通用）

| 位置 | 事件 |
|------|------|
| 0~10% | 开场影像 + Theme Stated |
| 10~25% | 催化剂 → 跨入门槛 + **第 1 个 set piece** |
| 30~50% | Fun & Games（set piece 段）→ Midpoint（虚假）|
| 50~75% | 对手计划推进 / 背叛 / 失去 → **All Is Lost（75%，全片最低点）** |
| ~80% | 至暗时刻 + Synthesis（B 故事给出解法）|
| 85~95% | 高潮（道德抉择）+ 收束 |

**强度曲线不是直线爬升**：
- 两次高潮之间必须压一场低强度戏（relief valve），否则高潮失去落差
- 75% All Is Lost 必须是全片最低点（比之前任何低谷都低），高潮才有冲劲

### 7.2 系列钩子（每单元结尾，4 型，不连续重复）

| 钩子类型 | 例子 |
|---------|------|
| 悬念 | 新威胁出现 / 倒计时开始 |
| 反转 | 本单元判断被推翻 |
| 情感 | 关系发生不可逆变化 |
| 信息 | 世界观揭示一条新信息 |

### 7.3 每单元高潮

- 每单元 1 个情绪高潮（可小）；系列大高潮必须落在**倒数 25% 内**
- 高潮 = 主角的**道德抉择**（§3.1 判据），不许外部打戏代选
- **全剧最低点**（系列 All Is Lost）放 **70~80% 总单元数**处（10 单元 = 单元 8），必须比之前所有单元的低谷都低（与 §7.1 单单元规则同构）；大高潮在其后 1~2 个单元内收束

### 7.4 系列引擎测试（0b 分集后执行，用户确认）

- **事件种子表**：每个单元一行"本单元引擎跑什么"（事件种子，一句话）
- 三判据：
  1. **pilot 之后想不出 3 集 = 引擎不成立** → 回 0a-2 改前提/主题，不硬分集
  2. 事件种子来源不雷同：5 条以上种子出自同一关系摩擦/同型反转 = 系列稀释
  3. 每个单元的种子至少产生一个主角"可失去之物"（赌注可感知，§2）
- 结果写入 `series.json` 的 `engine_check`（pass/fail + 理由）；不过 → 不进入 0c
- **franchise 四要素**（Rabkin）：concept + conflict + theme + **story pattern**——把"每单元重复的形状"写成一句话（"察觉威胁→出手保护→反噬危及另一个家庭"），并用 pilot 的后半段完整跑一遍
- **咬合测试**：concept 与 theme 必须能自然生出故事——"快写一个。现在再写 99 个"；写不出 → concept 与冲突没咬合，回 §2.5
- **引擎失压测算**（闭合长篇专用，替代"想不出 3 集"判据）：算出物质性引擎（交易/帝国/职位/那桩案）在第几单元失压 = 结尾位置；**集数由论证得出，不是被接受**；写 `engine_check.pressure_drop`
- 系列八型（Oberg）：程序 / 家庭 / 群像 / 职场 / 历史 / 悬疑 / 奇幻 / 单主角；选 1 型锁死基调，拿不准查素材库"案例数据"

### 7.5 单元结构与季形（多单元项目，0b 确认）

**幕尾四型（act out）**（每单元每幕末，类型不连续重复；幕断判据见 `series_format.md` 分幕规则）：反转（推翻既有判断）/ 新威胁（新力量或倒计时）/ 情感反转（关系不可逆）/ 情势变化（主角处境或目标翻转）

**隐形幕三判据**（流媒体 / 无广告位）：单元分 2~4 个**剧情日**，每剧情日 1 次**信息或权力转移**（转移 ≠ 悬念钩）；标志 = 换日 / 换地点与交通工具 / 核心问题转向

**A/B/C 线编织**（单元 ≥ 10 min）：A = 主线（payoff 落点）/ B = 关系主题线 / C = 副线喜剧；C 线 ≤ 25% 镜头，三线场景 5:3:2，C 不抢戏

**季形**（≥2 种，登记 `series.json` `season_shape[]`）：

| 类型 | 含义 | 用法 |
|------|------|------|
| 容器集 | 整单元压进一个带固定程序的公共场合（婚礼/葬礼/开票夜），程序节点 = 幕断 | 季终 / 周年集 |
| 瓶子集 | 2 人 + 1 小空间承载季级问题 | 省钱 / 关系深挖集 |
| tentpole | 一个大 set piece 单元（1/3、1/2 位置），"季的高光" | 每季 1~2 个 |
| 双集 | 1 事件跨 2 单元 | 仅当 1 单元装不下 |
| 季终减场加长 | 收尾单元场景数 < 季平均，每场加长（4 长柱：谈判/仪式/密谈/对峙）| 季末 1~2 单元 |
| 季级对称 | 一个可重复的量（价格/台词/动机）首尾各一次，中间不解释 | 每季至少 1 个 |
