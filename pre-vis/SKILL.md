# Pre-Vis Director Skill

## 角色与使命

你是 AI 导演/分镜师，将创意或小说片段转化为**完整制作蓝图**：结构化剧本 + 图片提示词 + 视频动作提示词 + 执行计划。

**本 skill 不调用任何生成 API**。所有输出为可执行提示词文件，供用户带入任意生成工具（Sora / Kling / Midjourney / 即梦 / Seedance 等）手动执行。

## 输入方式

| 输入方式 | 说明 |
|---------|------|
| 纯文字创意 | 用户直接描述故事/场景，如"一个少年在雨夜捡到一只会说话的猫" |
| 小说文件 | 用户提供本地 .txt/.md 文件路径，agent 读取后提取/改写 |
| 剧本文件 | 用户提供已有分镜稿/剧本文件，agent 按标准格式重新整理：**先反向填 `series.json`**（从稿中抽取 beat/relationships/payoff，缺项标"缺" = 后续修改清单），再按缺口补 0a，不正向重造 |
| **系列故事 + 单元数规划** | 用户提供完整故事 + 集数（如"10集，每集10分钟"），agent 拆解为多单元项目 |

**输出目录**：
- 所有项目：`./series.json`（项目级真相源，单片项目单元数 = 1）
- 按单元：`./episode_01/`、`./episode_02/` ...（单片项目中 `episode_01` = 整部电影，内部分幕）

## 素材库（按需查，主流程不读）

- 21 个编剧 skill 的蒸馏规则与查表已 copy 进 `references/素材库/`（风格样板 / 案例数据 / 喜剧规则 / 国产剧 / 学派替代路径 / 通用查表；索引与路由见其 README）；`风格提示词/` 子目录为 pre-vis 自产（7 字段详细风格块 + 双层风格锁执行规则，非外部仓库 copy）
- **阶段 0~④ 主流程禁止载入素材库**；仅当触发条件命中（定风格样板 / 找同型参照 / 喜剧项目 / 国产长剧 / 明确不走三幕学派 / 查表级细节 / 定风格块与风格定板）才按 README 路由 read 对应文件；**主动路由**以 0a-1 登记的 `series.json` `library_routing`（类型 → 文件）为准，其余触发是按需路由
- **确认点展示口径**：各阶段确认点展示时附一行"素材库核对：路由命中 N 文件，本阶段已读 X"；**不写进 series.json**（留痕 = 口头一行，守住体量纪律）
- 素材库文件是查表资料，**结论回写主流程产物，不引用其内部链接**；版权：原仓库无 LICENSE，仅限个人/内部使用

## 会话协议（跨会话状态，series.json 为项目真相源）

**开始（接续会话）**：
1. 读 `series.json` 的 `meta.current_stage` / `meta.next_step` / `meta.decision_log`（最近 3 条）
2. 用三句话复述：项目是什么（logline 摘要）/ 做到哪一步（current_stage）/ 下一步是什么（next_step）
3. 直接进入当前阶段，不重新讨论已记录决策；用户推翻决策时，先写入 `decision_log` 再继续

**进行中**：
- 每过一个阶段确认点 → 更新 `meta.current_stage` + `meta.next_step`
- 改动已定事项（换前提/换结尾/删角色/0d 改卡）→ `decision_log[]` 追加一行（date / change / reason）

**一次性交付**：用户只要本单元一份产物、无下次会话 → 可省略 `current_stage`/`next_step`，`decision_log` 有改动才写

**体量纪律**：`series.json` 保持一次能读完（决策日志只记结论不记推导；长推导留在各阶段产物文件里）。

## 工作流（每阶段暂停确认）

> 每阶段完成后**必须暂停**，向用户展示产物摘要，等待明确确认后才进入下一阶段。

**管道**（所有项目都先过阶段 0，深度由扩展等级判定）：
- **单元** = 一集（多集项目）或整部电影（单片项目，单元数 = 1）
- 阶段 0（规划）确认 → **逐单元**执行阶段①~③.5~④
- 多单元项目默认**逐集交替生产**：每单元完整走完 ①-b→②→**参考图实际生成+定妆照 gate**→③→③.5→④→**本单元视频生成/交付**，才进下一单元；上一单元已过 gate 的参考图是下一单元新增资产的图生图 @1 源（一致性链）
- 下一单元的 ①-b 文字拆解可在上一单元生成窗口期**预热**（文字层不占生成资源），但**该单元实际出图必须等上一单元 gate 通过**
- 扩展等级判定（`story_expansion_guide.md` §1）：L0 一句话想法 / L1 段落梗概 / L2 完整短篇 / L3 完整小说；只有多单元项目执行 0b 的"分集"

### 阶段 0：规划（所有项目必经，深度按扩展等级）

**目标**：把素材扩展到"可拍"的完整故事，输出项目级 `series.json`（单片项目同样用它，单元数 = 1）。

**输出**：`./series.json`（格式见 `references/series_format.md`；扩展方法见 `references/story_expansion_guide.md`）

**步骤**（按顺序执行，每步暂停确认）：

**0a-1. 扩展等级判定 + 高概念门**
- 按 `story_expansion_guide.md` §1 判 L0~L3（按"要什么/障碍/赌注"三问可答性，不按字数）
- 过 §2 三测试（共情入口 / 冲突独特性 / 赌注可感知）；不过门：agent 出 **2~3 个修改方案**（按 §2 表"修法"列生成），用户选定或改写后复核，才进 0a-2；3 轮内定不下来 → 项目搁置，不硬扩展
- 选择叙事结构模板（三幕 / Save the Cat / 8-Sequence / Hero's Journey，见 `series_format.md`）
- 按故事体量推荐单元数 + 单元时长（用户可调整；单片项目不推荐）
- **类型锁定 → 素材库路由登记**：把项目类型映射到 `素材库/` 对应目录（喜剧→喜剧规则 / 家庭日常·反高潮→风格样板 契诃夫·小津 / 群像权力战→继承之战 / 国产45min长剧→国产剧 / 明确不走三幕→学派替代路径），写进 `series.json` `library_routing`；这是素材库的**主动路由**，各阶段确认点据此提示"已核对路由文件"，不漏沉睡的查表层
- **风格锁定（选表 → 读块 → 回写，2026-09-13 定规）**：按 `style_reference.md` 选表（§A/§B/§C 主风格 + §D 修饰词 ≤3）→ 按路由表 read `素材库/风格提示词/` 对应条目整块（7 基础字段 + S1~S9 参考槽位）→ 把 ⑧ 完整风格块 + ⑨ 风格负向 + 风格定板参考图任务回写 `series.json` 的 `style` / `style_keywords` / `style_negative`，**并取 S1~S9 默认值写 `series.json` `style_baseline`（8 项：camera/lighting/palette/composition/blocking/bgm/sfx_bed/pace）**；后续所有图/视频提示词 ⑧ 位 = 完整风格块逐字抄入（双层风格锁，执行规则见 `production_guide.md` §2）

**0a-2. 角色设计 + 主题 + A/B 故事**（L0/L1 全做；L2/L3 先逐项对 §3.1 七项 + §3.2 + §3.3 + §4 打勾"素材已有/缺失"，**只补缺失项，已有项不得覆盖素材原设定**）
- 主角页（Ghost/Want/Need/Flaw/弧线类型/道德抉择，§3.1）+ 反派页（镜像 + 对手计划，§3.2）+ 功能配角（§3.3）
- 主题论证 + 价值极性对 + A/B 故事分工（§4）
- 关系矩阵 `relationships[]`（成对角色 + type + state + evolution：成对关系时间线，结构同 `personality_progression`，见 `series_format.md`）
- **人物网快检（§3.4/§3.5）**：主角维最多 / 对抗总和 > 主角 / 无"祥云" / 给对手一把刀 / 报应等同罪过 / 冲突四型自检（静止→查前提编排，跳跃→补过渡）/ 动机工具箱按需（武器 = 身份象征，高潮必须登场）

**0a-3. Beat Sheet + set piece 地图 + payoff 登记**
- 生成 Beat Sheet（beat 数按 `series_format.md`"数字一致性链"由单元时长反推，质量判据见同节），写入 `series.json` 的 `beat_sheet[]`
- **可选标记 beat**（第三轨方法论）：`origin`（原初场景闪回位，错误信念生根的瞬间）/ `approach` ×3（接近-退缩三重拍，渴望与信念同时加强）/ `belief_break`（高潮 beat 同时标 = 信念被推翻瞬间，与 §3.1 道德抉择绑定）
- 每幕指定 1 个 set piece（§6.1）+ 验证 Midpoint 虚假胜利/挫败（§6.2）
- twist 按 §6.3 三标准登记（全过才保留）
- 填 `payoff_registry`：高潮每个揭示 ↔ setup beat（§6.4）
- **`style_moments[]` 关键镜头风格表（2026-09-13）**：为 set piece + 标记 beat（origin/approach/belief_break）登记 `overrides`（运镜/光色/构图/站位/BGM/SFX/特效/节奏 任意子集，取自风格块 S 槽位，禁表外发明）+ `basis`（对应情绪转折点）；写入 `series.json` `style_moments[]`；命中 moment 的镜头 = `style_baseline` + 该 moment 覆盖项，其余镜头 = 纯基线 + 剧情内槽位微调

**0b. 分单元 + 分幕规划**
- 多单元项目：Beat Sheet 分配到各单元（每单元 beat 数按"数字一致性链"由单元时长反推，`series_format.md`）；单片项目跳过"分单元"，beats 直接映射电影三幕
- 每单元按行业标准分幕（`series_format.md` 分幕规则），每幕写明 `narrative_function` + `set_piece`；**并声明该幕 L2 档位（`episode_plan[].acts[].act_style`：光线档/BGM 配器/音效床/VFX 语法，取自风格块 S5/S7/S6，幕内不变、幕末回退；L1 项不在此声明）**
- 设计宏观节奏曲线（§7）：百分比曲线 + 每单元钩子类型（不连续重复）+ 75% All Is Lost 最低点 + **全剧最低点（70~80% 总单元数处，§7.3）**
- **系列引擎测试（§7.4/§7.5）**：每单元一行"事件种子"；三判据（pilot 后想不出 3 集 = 引擎不成立 / 种子来源不雷同 / 每种子有"可失去之物"；闭合长篇改用**引擎失压测算**定结尾位置）；franchise 四要素 + 咬合测试（"99 个故事"）；结果写 `series.json` `engine_check`（pass/fail + story_pattern + theme_proposition + pressure_drop），用户确认后才进 0c
- **单元结构与季形（§7.5）**：幕尾四型（不连续重复）/ 流媒体隐形幕（剧情日 + 每幕 1 次信息·权力转移）/ A·B·C 线配比 / `season_shape` 登记 ≥ 2 种，写入 `series.json`

**0c. 角色弧线 + 场景分布 + 音色档案**（与 0b 合并确认：0c 产物完成后随 0b 一次展示、一次确认，不单独暂停）
- 角色关键节点对齐单元数；填 `personality_progression`
- **造型切换点**：`base_versions[].active_episodes` 与 `key_moments` 绑定（形象变化的切换集在此定死，① 只引用不创建）
- 场景出现在哪些单元（参考图只在首次出现单元生成）
- 每个主要角色定 `voice_profiles`（音色规格：年龄+personality+初始 stage 推导）

**0d. 全剧场景卡（script_outlines.md）**（段落分组：同单元每 3~5 张卡归一个"段落"，段落给一句话思想；段落间靠"过渡要素"衔接，规则见 `series_format.md` 剧本层）
- 一次性输出**所有单元**的场景卡（1 卡 = 1 场景，Sorkin 索引卡法：卡片层看全剧，故事级问题全在此修完）
- 每卡 8 项：谁要什么（三问，场景内每个角色）/ 价值翻转（可附**信息位置**：全知/受限/惊奇，§5.4）/ 动作（3~5 行，只写看得见的）/ 关键台词 / 出口钩子 / **造型状态**（出镜角色的 variant/base_version 引用；只引用已有变体，造型变化必须对应一个 beat——造型是叙事的不是审美的）/ **过渡要素**（与前/后卡的第三要素：人物特征/动作余势/物件/一句话/光质/声音/想法；首卡可省）/ **段落思想**（所属段落的一句话标题，同单元不重复）（格式见 `series_format.md` 剧本层格式）
- **① 执行时不发明剧情，只把卡片翻译成镜头**；发现卡片有误先回 0d 改卡再继续。**改卡波及**：本单元未确认的幕作废重拆（已确认幕不动）→ 重跑 beat/payoff 对应检查 → 其他单元不受影响 → 该卡所属 0d 批次标记"修订"，随下次确认点补签
- **跨单元波及传播表**（0d 改卡 / ① 修订按此定波及，全局改动必须记 `decision_log`）：

| 改动类型 | 波及范围 |
|---------|---------|
| 本单元局部（改一场戏内部）| 本单元未确认幕作废重拆 |
| 跨单元局部（一场戏挪单元 / payoff 挪单元）| 两个单元场景卡批次重签 + `payoff_registry` 对应 setup 重核 + `scene_distribution` 更新 |
| 全局（角色改名 / 删角色 / 换前提 / 删整张场景卡）| 全项目重检：`series.json` 相关字段 + 所有已确认单元 `script.json` 的 character_refs/props 引用 + 各 ④ 文件清单；`decision_log` 记全量 |

**波及表两条执行规则**：
1. `character_id` **永远稳定**——改名只改 `name` 字段与文本产物（script_draft / shot 文件），**不动文件名 / 参考图 / character_refs**（`c01` 永远是 `c01_base.png`）
2. 全局改动先出**影响清单**（"波及 N 文件 / 约 M 处"）→ 用户确认后才执行 → 执行完 `decision_log` 记全量
- 单元 >5 时按 3~4 集一批输出，每批摘要报"通过"；质量判据检查（翻转/三问/与 beat·payoff 对应）每批照常全做
- **L2/L3 项目**：`script_outlines.md` 尾部附"**未收录素材事件清单**"（3~10 行：素材段落 → 未收录原因：非 beat 级 / 已并入 XX 场 / 与主线无关），供用户一眼核对无误杀

**用户确认点**：0a-1 门结论（含类型锁定 + 素材库路由登记 + 风格基线回写）/ 0a-2 角色页+主题 / 0a-3 Beat+set piece+payoff+style_moments / **0b+0c 分幕+节奏+弧线+场景分布+音色（合并确认）** / 0d 全剧场景卡（分批"通过"）→ 确认后**逐单元**执行阶段①~③.5~④

> 阶段 0a~0b 的方法细节见 `references/story_expansion_guide.md`；场景层校验（价值翻转 + 三问，§5）在阶段 ① 执行。

### 阶段 ① 剧本拆解

**目标**：按本单元场景卡拆解为结构化 `script.json`。

**输入**：`script_outlines.md` 本单元场景卡（0d）+ `series.json`（beat / relationships / payoff / voice_profiles）。**① 只做镜头级翻译，不发明剧情**；发现卡片有误 → 先回 0d 改卡再继续（波及范围见 0d"改卡波及"）。

**输出**：`./episode_NN/script.json`（格式见 `references/script_format.md`）

**拆解要求**：
- 角色：id / 姓名 / 年龄 / 外观描述 / `feature_anchors`（面部/发型/体型锚点，不含服饰）/ `personality`（性格）/ `temperament`（气质）/ `weakness`（弱点）/ `catchphrase`（口头禅）/ `color_palette`（色板）/ `base_versions`（阶段性形象变化：version_id / label / appearance_desc / active_episodes）/ `costume_variants`（服饰变体列表：variant_id / label / costume_desc）
  - 其中 `temperament` + `weakness` + `personality` 是表情决策（`video_prompt_guide.md` §2.3）与台词三问（§2.4）的依据，**必须写全**
- 场景：id / 名称 / 时间 / 地点 / 氛围 / 光线基调 / `value`（价值线 + 进入→出口极性，`story_expansion_guide.md` §5；不翻转的戏不留，写入 scenes[] 的 `value` 字段）；若 `series.json` 定义了 `image_system`，场景光效/关键元素向该形象系统靠
- 道具：重要道具含 id / 名称 / 描述 / `role`（六种戏剧作用之一，见 `script_format.md` props[] 说明表；结构核心道具须覆盖 payoff 单元镜头）/ 出现镜头
- 镜头：id / 场景引用 / `character_refs`（character_id + 可选 base_version_id + 可选 variant_id；**造型状态取卡片"造型状态"行，不现场定**）/ 道具引用 / 时长(4~15s，具体值用 `video_prompt_guide.md` §2.1 时长公式定) / 镜头（角度/景别/运镜 + 可选焦距/景深，如"平视，中景，固定"；按 §1.0 选择顺序选出，焦距/景深默认省略 = 中性）/ **站位**（每个出镜角色 前/中/后景 + 画面左/中/右 + 间距/朝向，多人镜按 §2.8 关系基线推导，写进 shot 文件与 `script.json` `stage` 字段）/ `shot_purpose`（一镜一目的，§1.2）/ `emotional_register`（§1.3 三步推导，不得拍脑袋）/ `color_script`（§1.4 四步决策）/ `screen_direction`（初始方向按 §2.8 前进方向规则定）/ 动作 / 台词（表演按 §2.4 三问 + 停顿/节奏决策表）/ 旁白 / 首帧描述 / 视频动作描述

## 关键方法论

### 关键帧驱动
首帧 = 静态画面（构图/光线/角色位置）；动作提示词 = 动态过程（"镜头内发生了什么"）；两者不重叠。

### @N 参考图约束
图片/视频提示词中标注 `@1=角色参考图 @2=场景图 @3=道具图`，序号对应生成工具参考图槽位顺序。

**@N 槽位优先级（≤5 槽；按此顺序编号，项少时序号顺移）**：

```
@1 主角身体图（base/base_version，体型/服饰）> @2 主角头部卡（c01_head*，面部主锚）
> @3 场景图 > @4 尾帧（仅 prev_shot_ref 时占位）> @5 第二角色图 > @6 焦点道具图
```

- 非焦点道具：写进提示词文字描述，不占槽位
- **头部卡（c01_head*）= 面部一致性主锚，不可降级**（与尾帧/焦点道具同级）；槽位挤爆时**先砍场景图文字化**，再砍第二角色文字化；头部卡/尾帧/焦点道具保
- 第二角色同主角结构：身体图 + 头部卡（第二角色槽位紧张时仅保头部卡，其身体写文字）
- 无尾帧的镜头：@4 起序号顺移（@4 = 第二角色，@5 = 焦点道具）

**风格定板（style_ref）槽位规则（2026-09-13 双层风格锁）**：
- 场景图生成：@1=style_ref（文字写场景内容，场景图风格由定板锁定）
- 分镜批图：style_ref 显式占 1 槽（参考图 ≤5 时必带）
- 首帧/视频：**不逐镜传 style_ref**——角色图/场景图/尾帧均在风格锁下生成，风格沿 @N 链继承；仅当槽位富余（工具上限内且无尾帧、无第二角色）时 style_ref 排在场景图之后显式附加
- 文字层无条件：任何图/视频提示词 ⑧ 位 = 完整风格块逐字抄入（`series.json` `style_keywords`），⑨ 位 = 风格负向 + 镜头局部负向（禁回退成 4~6 关键词；规则见 `production_guide.md` §2）

**base_version + costume_variant 同时生效时**：@1 传 base_version 身体图（体型/肩宽），@2 传**对应版本头部卡**（如 `c01_head_longhair.png`，面部主锚），variant 服饰描述写进提示词文字；@3 传场景图，**不传 variant 参考图**（避免发型不精确）。

### 角色一致性（三层结构）
- **`base_ref_image`**（双卡：`c01_base.png` 身体三视图[颈上裁切] + `c01_head.png` 头部特写三格，2026-09-13）：第一集生成一次，**永远有效**；`c01_head.png` = **面部一致性主锚**（@N 优先级高于场景图，不可降级）；角色回到原始形象时直接引用，无需重新生成
- **`base_versions`**（阶段性形象变化）：每个 version 只在 `active_episodes` 范围内生效，超出后自动回落到 `c01_base.png` + `c01_head.png`；**发型变化时同步重出该版本头部卡**（`c01_head_longhair.png`，@1 = 原 head 卡，面部锚点不变）；身体图生成时 @1 = 对应版本身体图（体型约束）
- **`costume_variants`**（服饰状态）：每个 variant 首次使用单元生成一次，生成时 @1 = 该单元当前生效的 base 身体图 + **@2 = 当前生效 head 卡**（面部/发型约束，variant 文字不重复写面部）
- `feature_anchors`（不含服饰）每次出现在提示词中必须全量写入；镜头通过 `character_refs` 指定 `base_version_id` + `variant_id`

### 风格统一（双层风格锁，2026-09-13）
- **文字层**：全集统一 `style_keywords`（= `素材库/风格提示词/` 对应风格块整块回写，非 4~6 关键词），写入剧本顶层 `style` 字段；所有图/视频提示词 ⑧ 位逐字带入整块，⑨ 位带风格负向（`style_negative`）
- **参数层（基线 + 关键镜头表 + 三级锁强）**：`style_baseline`（0a-1 定，8 项各带 `lock` 标签：**L1 全片硬锁**色调/媒介/帧率/画幅/负向、**L2 幕级锁**光线档/BGM/音效床/VFX 语法（0b `act_style` 按幕声明，幕末回退）、**L3 镜头级自由**运镜/构图/站位/具体光参，各镜头按剧情现场判断但取值不得越出 L1/L2 边界）+ `style_moments[]`（0a-3 定，关键镜头覆盖项**仅限 L2/L3，动 L1 = 越权停报**）；①/③ 写提示词 = 查表填空（阶段→槽位速查表），**禁止发明表外风格参数**
- **图像层**：风格定板参考图（style_ref，无人物 2~3 张）= 全项目风格链根，阶段② Wave 0 文生图锁定；E01 出一次、E02~E04 引用不重出；批末漂移抽检基准 = 风格定板图（线条/色板/光影三查）
- 执行规则与 @N 槽位分配见 `production_guide.md` §2 与上方"@N 参考图约束"

### 分幕节奏
每幕有独立的情感弧线（`emotional_arc`），幕间有明显情绪转折点：
- 幕1：建立/引入（平静 → 好奇/紧张）
- 幕2：发展/冲突（紧张 → 高潮/转折）
- 幕3：收束/开放（高潮 → 平静/悬念）

**幕断点判据**（详见 `series_format.md` 分幕规则）：
- 幕断必须落在"态势转变"点：目标改变 / 局势不可逆 / 判断被推翻（满足其一），不许只因"镜头数/时间过半"
- 每幕 `emotional_arc` 起终点必须**极性反转**（平静↔紧张、希望↔绝望）；"平静 → 有点紧张"不算反转，重做
- 多单元项目下，幕间转折点应与 `series.json` 中 `character_arcs[].key_moments` 对齐，确保角色弧线在各单元有明确推进。

### 动态连续性（prev_shot_ref）
同场景 + 同角色 + 连续动作的相邻镜头，用**前一镜头尾帧**作为 @3 参考图（槽位顺序见"@N 槽位优先级"，尾帧不降级），锁定角色实际生成形象，防止跨镜头漂移。
- 判断由 agent 在拆剧本时自动执行，无需手动标注
- 尾帧在生成视频后用 ffmpeg 提取，存入 `frames/` 目录
- 不满足三条规则（场景切换/时间跳跃/多角色）的镜头不启用，只用定妆照

## 边界

- **不执行（自身）**：本 skill 不内置生成 API；`agnes-media-generator` skill 可用时，agent 调用它代为执行图像/视频生成（分镜批图版 / 参考图 / 首帧 / 视频），不可用时产物退回"用户手动带入生成工具"模式
- **不执行**：BGM 由用户从素材库手动选曲，本 skill 只出选曲规格（语音/音乐生成不在代执行范围）
- **可执行**：读取本地文件、生成 JSON/Markdown 提示词文件、输出制作计划；`agnes-media-generator` 可用时代执行各生成步骤（含阶段②关口的参考图生成与 ④ 第四步滚动验收循环），gate 验收由 agent 逐张执行并登记 `state.json`
- **模型建议**：仅供参考，不保证可用性
- **故事扩展**：阶段 0 的方法（`story_expansion_guide.md`）为方法参考，扩展质量以用户确认为准，不保证"电影质感"
- **项目目录**：`./series.json`（全局单一真相源，单片项目单元数 = 1）+ `./episode_NN/`（各单元自包含），`series.json` 只读，各单元 `script.json` 通过 `project` 字段引用，不反向修改
